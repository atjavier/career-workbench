- (direction) Replace the current rigid streamed Coach response behavior with a typical chatbot-style realtime conversation.
- (capability) CAP-1: A user can send a message in one realtime Coach chat composer and see the local Coach reply progressively as natural conversational text.
- (constraint) Use LM Studio's local loopback streaming API only; preserve bounded context, consent, workspace/task isolation, server-owned model access, no tools/network/cloud fallback, and no automatic retry.
- (constraint) Natural Coach wording is presentation only; it cannot create tasks, claims, evidence, drafts, PDFs, or answer state, and final candidate answers remain explicitly selected from candidate chat messages.
- (decision) Use LM Studio's documented native /api/v1/chat SSE protocol, accepting named message.delta events and completing from chat.end; do not require a Coach reply to begin verbatim with the saved question.
- (decision) The chat UI has one message composer only: no separate static Coach fallback or answer textarea; a user explicitly selects one prior candidate message as the final answer or marks the task unknown.
- (question) Which LM Studio protocol should production use: documented native /api/v1/chat named SSE events or OpenAI-compatible /v1/chat/completions chunks? The local native endpoint was observed streaming successfully, while the user also identified an OpenAI-compatible endpoint.
- (assumption) Assumed Story 9.10's persistence, cancellation, bounded context, workspace isolation, and final-answer authority remain intact; this specification changes model-stream interpretation and chat surface behavior only.
