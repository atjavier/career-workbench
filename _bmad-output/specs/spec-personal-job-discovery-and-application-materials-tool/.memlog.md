- (direction) Adopt ARCHITECTURE-SPINE.md as a binding companion; preserve AD-1 through AD-10 and the local-only browser MVP scope.
- (capability) CAP-1: User can import source materials and individually review candidate evidence; success: only approved evidence is eligible for claims and retains source section plus review state.
- (capability) CAP-2: User can preserve an immutable Base Resume; success: drafts and exports identify their Base Resume and cannot overwrite it.
- (capability) CAP-3: User can configure Philippines-first entry-level role preferences; success: defaults prioritize fresh-graduate pathways, remote, then hybrid/onsite NCR without changing source policy.
- (capability) CAP-4: User can start a bounded manual refresh; success: selected-source outcomes and timestamps show completed, partial, or failed state and no scheduler/poll/retry is enabled.
- (capability) CAP-5: User can inspect normalized, deduplicated listings; success: attribution, original URL, freshness, unknown fields, and retained duplicate source records remain visible.
- (capability) CAP-6: User can configure permitted sources; success: only an approved method with policy/rate metadata can be enabled and disallowed sites remain handoff/manual-import sources.
- (capability) CAP-7: User can receive a transparent fit assessment; success: Strong, Potential, or Stretch reflects versioned evidence, requirements, gaps, seniority, location, and freshness without hiring predictions.
- (capability) CAP-8: User can trace fit reasoning; success: every match links to approved evidence and every requirement summary links to a short posting excerpt and source.
- (capability) CAP-9: User can request local AI drafts; success: LM Studio Qwen3.5-9B receives only selected listing plus approved evidence after an explicit local-data disclosure.
- (capability) CAP-10: User can review truthful ATS-safe drafts; success: unsupported generated or detectable edited claims block export without removing edit control.
- (capability) CAP-11: User can explicitly approve and export materials; success: every approved resume/cover letter yields a new immutable LaTeX and PDF Material Version with provenance.
- (capability) CAP-12: User can track saved opportunities; success: stage, local notes, follow-ups, attached materials, and ordered interview rounds remain local-authoritative.
- (capability) CAP-13: User can connect a Google Sheets tracker; success: Desktop OAuth requests only Sheets scope, verifies edit access, stores tokens in the OS vault, and can revoke locally.
- (capability) CAP-14: User can sync the tracker; success: stable IDs/revisions/hashes make writes idempotent, failures queue locally, and remote divergence requires explicit reconciliation.
- (capability) CAP-15: User can hand off to an original application URL; success: the host is named and the product neither fills nor submits employer forms.
- (capability) CAP-16: User can manage local data and audit history; success: scoped export/delete/restore, encrypted backups, 30-day trash, and metadata-only append-only audit are available in the UI.
- (constraint) Local-only browser MVP: bind only to 127.0.0.1; SQLite/app-data are authoritative; OS account is the access boundary; no public deployment or product login.
- (constraint) Architecture AD-1 through AD-10 are binding: manual-only policy-gated discovery, evidence-backed fit/claims, local LM Studio Qwen, local LaTeX, local-authoritative Sheets, lifecycle, and metadata-only audit.
- (constraint) No export until explicit review acknowledgement and no blocking claim warnings; no automated application actions or employer-form automation.
- (constraint) Google uses Desktop OAuth loopback and only the Sheets scope; Sheets is a mirror, not an authority; notes are local-only by default.
- (constraint) Materials use immutable resume.tex and a matching cover-letter LaTeX template; local TeXworks toolchain renders PDFs.
- (note) Non-goals: multi-user/coaching service, public hosting, scheduled/background retrieval, unauthorized access, cloud AI, ATS deception, hiring predictions, mass outreach, and application submission.
- (question) Which initial source catalog, approval records, and per-source request budgets will be enabled?
- (question) What TeX compiler command/path configured by TeXworks should first-run setup validate?
- (question) Is OS-account protection sufficient, or must local database/files also use application-level encryption on the target device?
