- (direction) User requested a machine-readable Epic 8 contract adopting finalized Architecture AD-13 and AD-14, covering profile validation, migration 0021, template integrity, LocalModelGateway consent/response, claim support, compatibility, and failure states.
- (capability) CAP-1: Adrian can save a valid versioned Candidate Profile so that later resume generation uses a stable identity, contact, and education snapshot.
- (capability) CAP-2: Adrian can view an immutable, digest-verified Resume.pdf template and preserve legacy Current Base Resume history without allowing legacy manual edits to create new materials.
- (capability) CAP-3: Resume Edit remains useful without AI through profile save and native template preview, while excluding manual editing, claims, approval, and export controls.
- (capability) CAP-4: Adrian can make one explicit, fully consented local Resume Coach request using only the exact configured profile, approved evidence, optional opportunity, and request text.
- (capability) CAP-5: A valid Coach response becomes a separate provenance-backed Material Draft whose candidate-facing claims each resolve to selected approved evidence and which only enters review through Use as draft.
- (capability) CAP-6: The application can apply migration 0021 and template bootstrap safely, preserve legacy data, and fail closed without partial drafts or unintended template replacement.
- (constraint) Preserve AD-13 and AD-14: all new data is local, append-only, UUIDv7 identified, digest-pinned, and migration is forward-only; legacy Current Base Resume records stay read-only history.
- (constraint) LocalModelGateway uses only LM Studio native v1 loopback with OS-vault token, exact validated model identifier, store:false, no response chaining, tools/MCP, CORS/LAN access, cloud fallback, retry, or raw operational logging.
- (question) Which Windows OS credential-vault adapter/library will implement the existing vault invariant without exposing the LM Studio API token to browser code or SQLite?
- (event) Coherence validation passed: six unique capabilities each have WHAT-focused intent and testable success; constraints bend design, non-goals are explicit, and the sole implementation gap is recorded as an open question.
- (event) Preservation validation passed: profile validation, migration 0021, template bootstrap/integrity, LocalModelGateway consent and response rules, claim support, legacy compatibility, accessibility, and all failure outcomes land in SPEC.md or its three spec-authored companions; no load-bearing source claim was dropped.
