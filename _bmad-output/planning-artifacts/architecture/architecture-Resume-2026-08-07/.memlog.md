- (direction) User selected Coaching path; architecture spine is the primary deliverable unless a later audience need warrants a companion artifact.
- (constraint) Preserve manual-only refresh; permitted-source policy compliance; provenance-backed fit; approved evidence before claims; explicit draft approval/export; local-authoritative Sheets mirror; and no automated applications.
- (decision) AD-1 [ADOPTED]: Use a managed modular monolith baseline: Next.js App Router with Supabase Free (Postgres, Auth, private Storage). Enforce a 750 MB application storage ceiling, reduced per-document upload cap, storage of structured source provenance rather than full job-page copies, and a user-downloadable local backup/export. The product must disclose and support manual resumption after free-tier inactivity pausing; no automatic backup is assumed. Binds all persistence, file storage, recovery, and deployment. Prevents a paid-storage dependency, opaque retention, and reliance on provider-only recovery.
- (version) Verified 2026-08-07: Supabase Free includes 500 MB database, 1 GB Storage, 5 GB egress, 50 MB maximum upload; projects can pause after 7 days of low activity and may be restored within 1 year.
- (decision) AD-1 [ADOPTED] amended: Use a local-first modular monolith: a Next.js App Router application runs only on loopback (127.0.0.1) on the user computer, with SQLite and a private app-data directory as authoritative persistence. The OS account and loopback-only binding are the access boundary; the MVP has no product sign-in and no public deployment. Google Sheets and AI are explicit outbound integrations only. Supabase is not part of the runtime. Binds all persistence, access, deployment, recovery, OAuth, and audit behavior. Prevents public exposure, cloud-provider storage dependence, background service execution, and unauthenticated network access.
- (direction) Runtime selection: local browser app chosen over desktop wrapper for fastest MVP delivery; future desktop packaging remains a deferred migration, not a runtime dependency.
- (decision) AD-2 [ADOPTED]: Local drafting uses Qwen3.5-9B served by LM Studio on 127.0.0.1 only. The app reaches LM Studio through one server-side LocalModelGateway using the current LM Studio API; require an LM Studio API token, disable CORS, local-network serving, model tool/MCP access, cloud fallback, and automatic retries. Each generation is isolated and receives only the selected Job Listing plus explicitly approved Candidate Evidence; request/response bodies are not persisted as operational logs. Binds AI generation, privacy, consent, configuration, and failure behavior. Prevents cloud transmission, uncontrolled model-side actions, LAN exposure, and use of unapproved candidate facts.
- (version) Verified 2026-08-07: LM Studio exposes native REST v1 at /api/v1/* and supports localhost serving with optional API tokens; OpenAI-compatible endpoints remain available. Its documentation recommends the v1 API for new projects.
- (decision) AD-3 [ADOPTED]: Fit is a deterministic, versioned evidence assessment, never an AI hiring prediction. A FitAssessment snapshots the Job Listing revision, Candidate Profile evidence revisions, preference revision, ruleset revision, derived label, factor outcomes, confidence/freshness, and short source excerpts. Strong requires substantial approved-evidence alignment and no known disqualifying seniority or location/work-style gap; Potential requires meaningful alignment with material gap or uncertainty; Stretch requires significant evidence, seniority, or location mismatch. Unknown/stale data lowers confidence and is disclosed, not assumed favorable. User Pursue/Priority state is independent and never changes the calculated label. Binds candidate evidence, job normalization, fit explanation, filtering, audits, and material generation. Prevents opaque rankings, retrospective label mutation, unsupported matches, and hiring-outcome claims.
- (decision) AD-4 [ADOPTED]: Candidate-facing claims are validated locally before approval/export. Each claim must link to one or more approved immutable Evidence revisions and, when tailored, to a Job Listing excerpt; unreviewed/rejected evidence never supports a claim. Generated or edited text lacking a complete support set is a blocking warning, not silently repaired. The Base Resume is immutable; all drafts and Material Versions retain an append-only provenance manifest. Binds evidence review, local model outputs, draft editing, approval, and export. Prevents fabricated claims, loss of provenance, and Base Resume mutation.
- (decision) AD-5 [ADOPTED]: Job discovery is adapter-based and source-policy-gated. A SourceConfiguration records an approved access method (official API, published feed, or policy-reviewed HTML retrieval), source policy revision/date, request budget/rate limit, enabled state, retention rule, and failure guidance. A user-started RefreshRun selects enabled sources; each adapter consumes only its source budget, stops on throttle/block/policy uncertainty, has no automatic retry, schedule, crawling expansion, credential reuse, proxying, or bypass. Sources without approved automated access are browser handoffs with local manual import. Source records retain attribution and minimal permitted provenance. Binds source setup, manual refresh, rate limiting, error display, normalization, and retention. Prevents unauthorized scraping and background retrieval while allowing permitted source-specific fetching.
- (decision) AD-6 [ADOPTED]: Google Sheets is an explicit, local-authoritative mirror. Use desktop OAuth with incremental least-privilege Sheets/created-or-user-selected-file access; store refresh tokens only in the OS credential vault and revoke/delete them on disconnect. The tracker has schema/version metadata and user-readable entity tabs: Applications, Materials, Follow-ups, and Interview Rounds. Each mirrored row carries stable entity UUID, local revision, last-synced content hash, and last sync timestamp; corresponding Sheets developer metadata anchors the row identity through row moves. Sync is an explicit visible attempt following a user mutation or Sync now, writes idempotently, and queues failures locally. Remote divergence is detected using prior hash/revision and resolved by a user-confirmed local-vs-Sheet reconciliation; no side silently overwrites the other. Notes stay local-only unless individually opted into mirroring. Binds OAuth, token storage, workbook schema, sync, conflicts, and revocation. Prevents duplicate rows, a second authority, token leakage, and silent loss of edits.
- (version) Verified 2026-08-07: Google recommends incremental OAuth authorization and secure token storage; Sheets developer metadata can associate values with rows and remains associated when rows move. Sheets API supports batch updates.
- (decision) AD-7 [ADOPTED]: The local web UI owns data lifecycle controls. It exposes a Data & Storage area for scoped export, deletion, restore, and storage usage. Active local data is retained until user deletion; ordinary deletes enter a 30-day local trash, sensitive items may be permanently deleted immediately after explicit confirmation, and purge is permanent. Dependency-aware delete previews identify derived drafts/material versions and never mutate the immutable Base Resume. The app supports encrypted user-downloadable backup/export archives. Google disconnect immediately removes the local OAuth token and sync state; it clearly states that prior remote Sheet data remains under the user Google account for separately managed deletion. Binds retention, deletion, recovery, exports, and audit events. Prevents undiscoverable local data, accidental provenance loss, and implied deletion of third-party copies.
- (decision) AD-8 [ADOPTED]: LaTeX is the canonical editable material source. The existing resume.tex is an immutable Base Resume template; each tailored resume is rendered from a versioned template copy plus structured, provenance-validated content. A new cover-letter LaTeX template must reuse its document style (A4 geometry, typography, links, and plain ATS-readable output) while carrying a distinct letter layout. The local model produces structured content only; a deterministic renderer escapes text and fills approved template slots, then a local LaTeX compiler creates the PDF. Explicit review acknowledgement plus zero blocking claim warnings are prerequisites to each new MaterialVersion export; each version retains .tex, PDF, content manifest, template digest, and provenance manifest. Binds drafting, formatting, exports, versioning, and auditability. Prevents formatting drift, model-authored executable TeX, export before evidence review, and Base Resume overwrite.
- (question) Which local TeX distribution/compiler currently builds resume.tex? No latexmk, pdflatex, or tectonic executable was found on PATH; choose/configure one before implementation.
- (decision) AD-9 [ADOPTED]: PDF rendering is local through the LaTeX toolchain configured for TeXworks. First-run setup discovers or accepts the compiler command/path, validates it against the immutable Base Resume template, and records a non-secret toolchain fingerprint. Rendering runs in a version-specific temporary work directory with escaped structured inputs; compile errors preserve the approved draft and expose only actionable diagnostics. No cloud rendering or background compilation is permitted. Binds export setup, rendering, diagnostics, and recovery. Prevents environment-specific format drift and loss of an approved draft on render failure.
- (decision) AD-10 [ADOPTED]: Auditability is local and append-only. Record metadata-only events for source refreshes, evidence review, fit calculation, local-model generation, approval/export, Sheets sync/reconciliation, OAuth lifecycle, and data recovery/deletion. Events contain timestamp, actor=local-user, entity/version IDs, action/outcome, and content hashes where applicable; never raw documents, prompts, model output, tokens, or credentials. Audit history is visible and optionally included in encrypted backup export. Binds audit, privacy, recovery, and operational diagnostics. Prevents unverifiable state changes and leakage through logs.
